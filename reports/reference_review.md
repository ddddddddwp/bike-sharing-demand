> 说明：这些照片至少包含三类工作：**6 类场景图像分类（CNN / ResNet-18 / 知识蒸馏 / EWC 持续学习）**、**伪装目标检测（ESCNet）**、**低光图像增强（Retinexformer）**。对 Bike Sharing 项目最有借鉴意义的是第一类，它的“基础对比 + 模型延伸 + 消融 + 局限”结构可以直接迁移到表格预测项目。

## 1. 参考 PPT 做了什么

### 1.1 项目结构

参考项目不是“只训练一个模型”，而是明确分成两部分：

| 部分 | 模型 | 作用 |
|---|---|---|
| 基础对比 | CNN 基准 / Teacher | 建立六分类基线，并提供蒸馏监督 |
| 基础对比 | ResNet-18 从头训练 | 比较残差网络与基础 CNN |
| 模型延伸 | 蒸馏 Student | 用更少参数保留分类能力 |
| 模型延伸 | EWC 持续学习 | 顺序学习类别，缓解旧知识遗忘 |

这个结构值得直接学习：**先有一个可信基线，再有一个“为什么还要做”的延伸问题**。

### 1.2 实验内容

1. **学习率实验**：0.01 / 0.03 / 0.05 / 0.1 / 0.2 五档；5 折 CV 的 RMSLE、MAE；每折 best epoch / stop epoch；训练分钟数；收敛曲线。
2. **模型对比**：CNN vs ResNet-18，同样 27 轮、同 seed、同 batch、同增强；同时报告验证准确率和参数量（1.18M vs 11.18M）。
3. **预处理消融**：水平翻转概率 0 / 0.25 / 0.5；旋转 0° / ±10° / ±20°；两个模型分别比较；并明确写出 batch size 不同这一混杂因素。
4. **知识蒸馏**：Teacher/Student 结构、温度 T=5.0、权重 α=0.5、软损失乘 T²；报告参数量压缩 24.18 倍、准确率下降 3.90 个百分点、训练时间缩短 51.6%。
5. **持续学习**：三个任务依次到来；无正则化 vs EWC λ=500；画旧任务准确率随新任务学习的变化；结论是 EWC 缓解断崖式下降。
6. **局限**：训练时间不等于推理延迟、没有 FLOPs/部署实测、λ/α 未系统搜索、Fisher 矩阵存储随任务数线性增长。

### 1.3 他们的表达模板

每张实验页基本是同一个结构：

```text
标题：实验问题
设置：控制变量 / 数据 / 轮次 / seed / batch
结果：表格 + 曲线 + 精确数字
结论：一句话说明“是否值得”
局限：测量条件、混杂因素、未做的部分
```

项目结构页则用一张表回答“每个模型为什么存在”。

## 4. 建议的 6 个横向拓展实验

### 实验 A：超参敏感性与收敛（P2）

**目的**：回答“当前配置是不是拍脑袋”。

- `learning_rate`：0.01 / 0.03 / 0.05 / 0.1
- `num_leaves`：15 / 31 / 63 / 127
- `n_estimators`：配合 early stopping（50 轮）
- `min_child_samples`：10 / 30 / 50

**输出**：

- 表：CV RMSLE / MAE、best_iter、stop_iter、训练秒数；
- 图：同一折的 validation RMSLE vs iteration；
- 结论：默认配置是否在平台区，继续调参的收益是否小于折间波动。

这是参考 PPT“学习率五折成绩与实际轮次”的直接迁移。

### 实验 B：特征/预处理消融（P1 + P2）

**目的**：回答“哪些特征真的有用”。

建议做 5 组对照，固定 time_v2、固定 LightGBM：

| 组 | 内容 |
|---|---|
| B0 | 日历 + 原始天气 |
| B1 | B0 + 周期编码（hour/weekday/month sin/cos） |
| B2 | B1 + 目标聚合（hour/weekday/hour×workingday 均值） |
| B3 | B2 + 交互（temp×season、humidity×weather） |
| B4 | B3 + 去掉 `year` / `day` 的稳健性对照 |

再加两个预处理对照：

- 目标：Poisson raw count vs log1p + L2；
- 类别：LightGBM 原生 category vs one-hot / ordinal。

**输出**：`p1_feature_ablation.csv`、特征数/训练时间/RMSLE 表、结论“目标聚合是否值得”。

这是参考 PPT“翻转/旋转消融”的表格化迁移。

### 实验 C：模型效率与轻量模型（P2）

**目的**：回答“精度提升值不值成本”。

对比：

- Full LightGBM（当前配置）
- Small LightGBM（num_leaves=15，n_estimators=200）
- Top-k 特征 LightGBM（k=10 / 20 / 36）
- Ridge / RF

**指标**：

- 特征数 / 树数 / 叶子数；
- 模型文件大小；
- 训练时间；
- 单条/1,000 条推理延迟（固定 CPU、线程数、warm-up）；
- CV RMSLE。

**输出**：`p2_efficiency.csv` + Pareto 图（RMSLE vs latency / size）。

参考 PPT 的“参数量 1.18M vs 48,838、训练时间 165.6 vs 80.08 分钟”就是这种表。

### 实验 D：时间漂移与持续学习（P2 + P3）

**目的**：回答“模型过几个月会不会失效”。

对比三种策略：

1. **Static**：只用 2011 训练，预测 2012；
2. **Sliding window**：每次用最近 6/12 个月训练；
3. **Incremental**：在旧模型上增量更新（LightGBM `init_model`）或按月重训。

**评估**：

- 按月 RMSLE 曲线；
- 旧月份“遗忘”程度（更新后旧月误差上升多少）；
- 新月份“适应”速度；
- 与静态模型的总体 RMSLE/MAE 对比。

**输出**：`p3_temporal_shift.png`、`p3_temporal_shift.csv`。

这是参考 PPT“三个任务依次到来 + EWC”的表格预测版本；不需要真的实现 EWC，重点是**顺序更新与遗忘**。

### 实验 E：统计严谨性（P2 + P3）

- 3–5 个 seed 重跑 LightGBM；
- 报告 mean ± std；
- 对 RMSLE 做 bootstrap 95% CI；
- 模型间做 paired test（同一折/同一 seed 的配对 Wilcoxon 或 t-test）；
- 明确“单 seed 的 +0.001 不算结论”。

**输出**：`p3_stability.csv`、`p3_ci.png`。

参考 PPT 用 5 折 + seed 42，但没有多 seed；你可以比它更严谨。

### 实验 F：不确定性（P3，可选）

- LightGBM quantile regression（α=0.1/0.5/0.9）；
- 或 conformal prediction；
- 报告 interval coverage / width；
- 对比点预测与区间预测在高需求/恶劣天气下的表现。

**输出**：`p3_intervals.png`、`p3_interval_metrics.csv`。

这不是参考 PPT 的内容，但能让 P3 从“点预测评估”升级为“风险可控的预测”。

## 7. 不要照搬的地方

1. 参考项目是图像分类，**不要把 flip/rotation 直接搬到表格数据**；对应的是特征变换/时间扰动/天气扰动。
2. 参考项目用 EWC 解决“任务序列遗忘”；你的表格项目更适合做“静态 vs 滑动窗口 vs 增量重训”，不要为了方法而方法。
3. 参考项目的“参数量/FLOPs”在 LightGBM 上要换成“树数/叶子数/模型大小/推理延迟”，不要伪造 FLOPs。
4. 参考项目的训练时间是在 GTX 1650 上测的；你的项目要写清 CPU/线程数/是否多进程，训练时间和推理延迟分开报。
5. 参考项目有 batch size 不一致的混杂因素，并明确写出来；你做消融时也要固定随机种子、折、特征、线程数，并注明无法固定的因素。

## 8. 一句话总结

参考 PPT 的核心不是“用了 ResNet/蒸馏/EWC”，而是：**先建立可信基线，再用一个明确的延伸问题（效率、遗忘、鲁棒性）把项目从“调包”变成“研究”**。  
你的 Bike Sharing 项目现在有扎实的 P1/P2/P3 主线，缺的是 **横向三条线：效率线、时间线、统计线**。把这三条线补上，报告和答辩的厚度会明显不一样。
